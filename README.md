# `cosign2`

`cosign2` is a Rust library and CLI tool for signing firmware/application images.
The library part is `#[no_std]` and intended to be used in bootloaders.

## Installation

To install the CLI from source:

```bash
cargo install --locked --git https://github.com/Foundation-Devices/cosign2.git cosign2-bin
```

Or with Nix:

```bash
nix run github:Foundation-Devices/cosign2 -- --help
nix profile install github:Foundation-Devices/cosign2
```

`nix develop` opens a shell with the Rust toolchain to work on the repository.

## CLI Flags

The following commands are supported:

```
Usage: cosign2 <COMMAND>

Commands:
  dump  Dump the header contents to stdout
  sign  Sign a binary file
  help  Print this message or the help of the given subcommand(s)

Options:
  -h, --help     Print help
  -V, --version  Print version
```

The dump command prints header contents to stdout:

```
Dump the header contents to stdout

Usage: cosign2 dump [OPTIONS] --input <INPUT>

Options:
  -i, --input <INPUT>              The binary file
      --header-size <HEADER_SIZE>  Size of the header in bytes [default: 2048]
  -h, --help                       Print help
```

The sign command is used to sign the binary:

```
Sign a binary file

Usage: cosign2 sign [OPTIONS] --input <INPUT>

Options:
      --pubkey <PUBKEY>
          The public key in hex, verified against the secret key to avoid accidental signing
      --secret <SECRET>
          Path to PEM-encoded secret key
  -c, --config <CONFIG>
          Path to config file
  -i, --input <INPUT>
          The binary file
      --in-place
          Update the binary file in place
  -o, --output <OUTPUT>
          Path to write the signed binary file
      --binary-version <BINARY_VERSION>
          Version to write in the header
      --developer
          Developer mode, signs with a single key
      --target <TARGET>
          Target device. Valid values are "atsama5d27-keyos"
      --known-pubkey <KNOWN_PUBKEY>
          Known public keys to accept signatures from, separated by commas
      --header-size <HEADER_SIZE>
          Size of the header in bytes [default: 2048]
  -h, --help
          Print help
```

Signing a binary without a header requires a target and a binary version, from the CLI or
the config file. The target accepts `atsama5d27-keyos` and `nrf52-ble`, and is stored in the
header magic.

The header size must be between 256 and 4096 bytes, and `dump` must be given the size the
binary was signed with.

## Trust Model

A header has two signature slots, and both signatures cover the same digest of the header
fields and the binary hash.

- A release header is signed twice, by two different keys from the known public keys, and
  verifies as fully trusted. Signing a binary that already carries one signature adds the
  second one.
- A developer header (`--developer`) is signed once, with a key that is not a known public key,
  and verifies as third party.

The known public keys are the verifier's list of release signers, given with `--known-pubkey`
or `known_pubkeys`.

## Configuration File

To avoid repeating CLI flags whenever running the tool, the user can specify a config file.
The config file is in TOML and has the following format:

```toml
pubkey = "02118f59082b8e26753c1cab1bfead3259344c03312cbb4ff7bdecceb915e92c9b"
secret = "/absolute/path/to/private_key.pem" # NOTE: the path must be absolute
known_pubkeys = [
    "03bf014e1a37a113089bea7b50ee9bd7733189ecd6afb7e051a6e95f99b97da5e9",
    "03040e47c1cde8978085bdc8b44df85e7c0b2e1ea586697b5d385e523d3f908bc3",
    "038de8dd1cbad8bf1da7ff64b8a9b4a375f0205eff41f7f9dca8e91c4cf0951daa",
    "03cb8e4219d3c8f269ab2ed3acb71a4b1722c76a0c348ea11fa79b4639bef45094",
]
target = "atsama5d27-keyos"
```

All the fields are optional. Specifying the same argument in the CLI and in the config
file results in an error.

To use the config file, pass it to the sign command:

```bash
cosign2 sign --config path/to/config.toml -i unsigned.img --binary-version 0.0.121 -o signed.img
```

## Generating keys

### Generate `secp256k1` private key

This command uses OpenSSL to generate the private key in PEM format.

```bash
openssl ecparam -noout -genkey -name secp256k1 > ~/cosign2-priv.pem
```

### Generate compressed public key

This command uses the private key generated earlier and generates a hex string of a compressed public key
to use with the `cosign2` tool.

```bash
cat ~/cosign2-priv.pem | openssl ec -pubout -conv_form compressed -outform DER | tail -c 33 | xxd -p -c 65
```

### Applying the generated keys to the configuration TOML file

Update the configuration toml file:

1. Set the `secret` field to the path of the private key file generated earlier.
2. Set the `pubkey` field to the public key string generated by the command above.
3. Remove `known_pubkeys` if present, or update it to only include the official release
   public keys. Your own `pubkey` is a developer key and must not be listed.

## Examples

### Sign a Binary File

```bash
cosign2 sign \
    --secret private-key.pem \
    -i unsigned.img \
    --target atsama5d27-keyos \
    --binary-version 0.0.121 \
    -o signed.img
```

### Dump the Header Contents

```bash
cosign2 dump -i signed.img
```

### Sign a Binary File with Config

```bash
cosign2 sign \
    -i unsigned.img \
    --binary-version 0.0.121 \
    --config my-config-file.toml \
    -o signed.img
```

## Library

The `cosign2` crate is not published on crates.io; depend on it by git revision:

```toml
cosign2 = { git = "https://github.com/Foundation-Devices/cosign2.git", rev = "<commit>" }
```

It has no default features:

- `std`: enables `Header::parse_streaming`, which verifies a binary read in chunks.
- `semver`: requires the header version to be a semantic version.

The library does no cryptography itself: the caller implements the `Sha256`,
`Sha256Streaming`, `Secp256k1Sign` and `Secp256k1Verify` traits.

- `Header::sign_new` builds and signs a header; `Header::parse` verifies one against the known
  signers and reports its `Trust`.
- For signers that never see the binary, `Header::new_unsigned` builds a header with both slots
  empty. A signer holding that header and the binary hash recomputes its digest with
  `Header::parse_unsigned` and signs `Header::digest`. `Header::insert_signature` adds each
  signature, and `Header::serialize` writes the signed header.
